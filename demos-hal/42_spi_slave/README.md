# 42_spi_slave — STM32H750 SPI2 从机(Slave) Demo

正点原子 **M100Z-M7 最小系统板(STM32H750VBT6)** 的 SPI2 从机实验工程。

---

## 1. 功能

| 项目 | 说明 |
|------|------|
| 外设 | SPI2，**从机模式** |
| 引脚 | `PB12=NSS` `PB13=SCK` `PB14=MISO` `PB15=MOSI`（AF5） |
| 时序 | **Mode0**（CPOL=0, CPHA=0），MSB 先发，8bit；模式由 `SPI_DEMO_MODE` 可选 0~3 |
| Master 时钟 | 支持 **100kHz ~ 10MHz**（SPI2 内核时钟 PCLK1=120MHz） |
| Master 写 | NSS 上升沿（一帧结束）后，从机把本帧数据以十六进制从 **串口1 @115200** 打印，并**自动判读位对齐** |
| Master 读 | 从机 MISO 恒定循环返回 16 字节应答，V1.4 默认 **16 个 `0xA5`**（位对齐探针） |
| 单帧上限 | **256 字节**（`SPI_FRAME_MAX_LEN`，超长视为 NSS 漏沿丢弃） |
| 帧间间隔 | NSS 高电平建议 ≥ 50us |

---

## 2. 接线

### SPI 四线（必须全部接，且必须共地）

| STM32 (M100Z-M7) | 方向 | Master (RK3576 等) |
|---|---|---|
| `PB12` NSS | ← | CS / SS |
| `PB13` SCK | ← | SCLK |
| `PB14` MISO | → | MISO |
| `PB15` MOSI | ← | MOSI |
| `GND` | — | GND（**必接**） |

> **NSS 一定要接。** SPI 协议本身没有"帧"的概念，从机完全靠 NSS 上升沿判断一帧结束。
> 不接 NSS 就不会打印，数据也会粘连。

### 串口（看打印）

板上没有 USB 转串口芯片，`PA9(TX)/PA10(RX)` 引在 **P3 调试排针**（4x2，丝印 `SWD & USART1`）。

| STM32 | Mini HS-DAP / USB-TTL |
|---|---|
| `PA9` (TX) | RXD |
| `PA10` (RX) | TXD |
| `GND` | GND |

串口参数：**115200-8-N-1**，用 XCOM / SSCOM / MobaXterm 打开对应 COM 口。

## 3. 工作原理（V1.3 环形 DMA 常驻架构 + V1.4 位对齐自诊断 + V1.5 硬件 NSS）

SPI 使能一次就**不再关闭**，收发 DMA 都配成 **CIRCULAR（环形）模式常驻运行**，
只用 `NSS(PB12)` 的上升沿中断来"切割"帧：

```
        ┌────────── 一直使能，永不停 ──────────┐
SPI2 ───┴──────────────────────────────────────┴───
   RX DMA (DMA1_Stream0, 环形512字节)  ← 连续写入环形缓冲
   TX DMA (DMA1_Stream1, 环形16字节)   → 应答pattern常驻FIFO

NSS 上升沿 ──► EXTI ──► 读DMA剩余计数NDTR
                       本帧长度 = (上次NDTR − 本次NDTR) & 511
                       本帧数据 = 环形缓冲对应区间（含回绕处理）
                       ──► Cache失效 ──► 拷到影子缓冲 ──► 置打印标志
主循环      ──► 检测标志 ──► 十六进制打印（不在中断里做慢速打印）
```

### 为什么这么设计

V1.0~V1.2 用的是"每帧停下 SPI/DMA → 处理 → 重新武装"的模型，在 STM32H7 上会踩三个坑：

| # | 坑 | 后果 |
|---|---|---|
| 1 | H7 的 SPI 从机必须"**先武装好，再来时钟**" | 每帧重新武装的窗口里如果 Master 已开始打时钟，**首字节丢失/错位** |
| 2 | H7 的 SPI **TX FIFO 会被 DMA 预填充**，而 `SPE=0` 并不保证清空 FIFO | 反复"停/启"会让 Master 读到**上一次残留在 FIFO 里的旧字节** |
| 3 | HAL 的 `HAL_SPI_TransmitReceive_DMA()` 会顺带开 OVR/UDR/FRE/MODF 中断并维护内部 State 机 | 一旦 DMA 报错就把流停掉、State 置 ERROR，之后数据全乱、重新武装还直接返回 `HAL_BUSY` |

V1.3 的环形常驻模型把这三个坑一次性绕开：**从机在任何时刻都是"武装好"的状态**，
不存在重新武装窗口，也不存在 FIFO 残留。

### 几个关键设计点

- **软件 NSS**：`SSI=0`，从机常选中（MISO 常驱动），只适用于**单从机**总线。
- **TX 缓冲长度 = 应答 pattern 长度 = 16 字节**。DMA 环形长度正好等于 pattern 长度，
  FIFO 里预装的永远是 pattern 的连续片段，所以 Master 每次读 16 字节
  **必然**拿到完整的 pattern，不受帧起点漂移影响。
- **V1.4 把应答 pattern 从 `30 31 ... 3F` 换成 16 个 `0xA5`**，原因见 3.1 节。
  把 `SPI_TX_PATTERN_MODE` 改成 `1` 可以切回旧的递增 pattern。
- **V1.5 把片选改成硬件 NSS**（`SPI_NSS_MODE = 0`）：PB12 走 `AF5` 交给 SPI2 硬件做真片选，
  NSS 无效（高）期间 SPI 直接忽略 SCK。
  V1.4 及以前用**软件 NSS**（手动清 `SSI`，从机"永久选中"），于是 Master 在帧间切换 CS 时
  SCK 线上的任何扰动都会被从机当成一个数据位，**整帧因此偏移 1 bit 且永不恢复**。
  现场证据（两条互相印证）：

  | 方向 | Master 发 | 从机/仪器收到 | 关系 |
  |---|---|---|---|
  | RX（MOSI） | `A5 A5 A5 ...` | `A6 D2 D2 D2 ...` | `D2` = `A5` **循环右移 1 位** |
  | TX（MISO） | （从机应答 `30 31 ... 3F`） | `70 72 74 76 78 7A 7C 7E` | = `38~3F` 各**左移 1 位** |

  这也是为什么**"递增斜坡"是最坏的测试数据**——`30 31 32...` 被任何位偏移后
  仍然是漂亮的递增序列，肉眼和逻辑分析仪都分不出"数据源错"和"位偏移"。
  把 `SPI_NSS_MODE` 改成 `1` 可以退回旧行为做 A/B 对比。
- **不启用任何 DMA 中断**：全片唯一中断源是 `NSS` 的 EXTI。
  另外 `HAL_DMA_Start_IT()` 会无条件打开 DMA 的 TC/TE/DME 中断，代码里显式关掉了。
- **关掉了 DMA 中断服务函数的内容**（`DMA1_Stream0/1_IRQHandler` 留空占位）。
  这样链接器能丢掉 `HAL_DMA_IRQHandler`/`HAL_DMA_Abort_IT` 约 **4KB** 代码 —— 
  见下面第 5 节的 32KB 限制说明。
- **Cache 一致性**：缓冲区 32 字节对齐、位于 AXI SRAM（`0x24000000`）。
  D-Cache 强制透写；RX 方向 DMA 写内存后 CPU 读前做 `SCB_InvalidateDCache_by_Addr`。
- **毛刺帧过滤**：Master 板上电/复位瞬间 SCK 抖动会被从机当成时钟、MOSI 悬空为高
  → 收到满屏 `FF`。本工程**静默丢弃全 0xFF 帧**不打印。
  （若业务上确实要传全 0xFF 的数据帧，删掉 `main.c` 中标注的那一段即可。）

### 3.1 为什么把应答 pattern 换成 0xA5（位对齐探针）

**递增斜坡 `30 31 32 ... 3F` 是诊断上最坏的选择。** 它是一条斜坡，任何一个位的偏移，
移完仍然是一条递增斜坡：

| 实际线上的数据 | 逻辑分析仪 / 上位机看到的 |
|---|---|
| `30 31 32 33 34 35 36 37`（正确） | 干净漂亮的递增，**看着完全正常** |
| 整体偏 1 bit | `60 62 64 66 68 6A 6C 6E`（**还是递增**） |
| 整体偏 1 bit，且起点落在 pattern 后半段 | `70 72 74 76 78 7A 7C 7E`（**还是递增**） |

三种情况肉眼看都像"递增"，这就是之前"看着不对、但说不清错在哪"的根源 ——
用逻辑分析仪抓到的 `70 72 74 76 78 7A 7C 7E`，正是斜坡整体移位后的结果，
和"数据源错了"看起来一模一样。

**`0xA5 = 1010_0101` 的 8 种循环移位互不相同：**

```
A5  →  4B  →  96  →  2D  →  5A  →  B4  →  69  →  D2  →  (回到 A5)
```

于是位偏移量可以**一眼读出来**：

| 读到 | 结论 |
|---|---|
| `A5 A5 A5 ...` | 位对齐正确 |
| `4B 4B 4B ...` | 整体偏 1 位（一个方向） |
| `52 52 52 ...` | 整体偏 1 位（另一个方向） |
| `96 96 96 ...` | 整体偏 2 位 |

而且 `0xA5` 只有 **1 字节周期**，环形缓冲的"相位"是多少都不影响正确性 ——
不会再有"读到 pattern 第二半段"的困扰。

**如果确认是位偏移**：把 `main.c` 顶部的 `SPI_DEMO_MODE` 依次改成 `1 / 2 / 3`
重新编译烧录（对应 Mode1/2/3），同时把 Master 改成同一模式，总有一个能对上。

## 4. 上电自检与诊断输出

### 4.1 信号线自检（每次上电打印一次）

保持 Master 上电，从机用**内部上拉/下拉对比**判断每条线是否真被外部驱动：

```
---- 信号线自检(Master保持上电, 用内部上下拉对比, 只作参考) ----
  SCK  (PB13): 外部驱动为低
  MOSI (PB15): 外部驱动为高
  MISO (PB14): 悬空(正常, 由STM32驱动)
  NSS  (PB12): 外部驱动为高(空闲)
```

出现 `悬空/未接 !!` → 这根线没接到 Master，先查线。

### 4.2 寄存器快照（每次上电打印一次）

```
---- 寄存器快照 ----
 SPI2  : CR1=... CFG1=... CFG2=... SR=...
 DMA_S0: CR=... NDTR=512 PAR=... M0AR=... (RX, 环形512字节)
 DMA_S1: CR=... NDTR=16  PAR=... M0AR=... (TX, 环形16字节)
```

`CR` 的 bit10(`MINC`) 与 bit8(`CIRC`) 应都为 1；`NDTR` 应等于缓冲大小。

### 4.3 运行中诊断（每 3 秒一次，只在有变化时打印）

```
[诊断] NSS边沿=12  毛刺帧=0  超长帧=0  SPI错误=0  FIFO排空超时=0
```

| 字段 | 含义 | 正常值 |
|---|---|---|
| `NSS边沿` | 收到多少次 NSS 上升沿 | 与 Master 发起次数一致 |
| `毛刺帧` | 被过滤掉的全 0xFF 假帧数 | Master 上电时会涨几次，之后不动 |
| `超长帧` | 超过 256 字节、被判为 NSS 漏沿而丢弃的帧数 | **恒为 0** |
| `SPI错误` | OVR/UDR/FRE/MODF 次数 | **恒为 0** |
| `FIFO排空超时` | RX FIFO 迟迟不空（DMA 可能卡住） | **恒为 0** |

### 4.4 位对齐自诊断（V1.4 新增）

让 Master **重复发同一个字节**（推荐 `0xA5`），从机在收到整帧字节完全相同时，
会自动反推它相对 `0xA5` 的循环移位量并直接给出结论。

**Master 端测试命令（RK3576 / spidev_test）：**

```bash
# 1) 验从机 RX + 位对齐：发 8 个 0xA5
spidev_test -D /dev/spidev2.0 -s 100000 -p "\xA5\xA5\xA5\xA5\xA5\xA5\xA5\xA5"

# 2) 验从机 TX：读回 8 字节，应该正好是 A5 A5 A5 A5 A5 A5 A5 A5
```

**对齐正确时：**

```
[SPI2 Slave] 收到 8 字节:
A5 A5 A5 A5 A5 A5 A5 A5

[对齐] 收到 8 个 0xA5 = 探针 0xA5 => 从机采样位对齐正确
```

**位偏移时：**

```
[SPI2 Slave] 收到 8 字节:
4B 4B 4B 4B 4B 4B 4B 4B

[对齐] 收到 8 个 0x4B = 0xA5 循环左移 1 位 => 位对齐偏了 1 位
       把 SPI_DEMO_MODE 换一个值(依次试 1/2/3)重新编译烧录,
       Master端同步改成同一模式再测一遍
```

读到"不是 `0xA5` 任何循环移位"的值 → 不是单纯位偏移，重点查**共地**、SCK 频率是否过高、
SCK 线上有无过冲振铃（长杜邦线 + 高频率最容易出这个问题）。

## 5. ⚠ Keil 版本限制：32KB

本工程用 **armcc V5.06u7 (AC5)** 编译，镜像大小约 **31908 字节**
（`Code=30072 RO=1776 RW=60`，另有 `ZI=5972` 不占镜像）。

如果 Keil 是 **Lite / 未注册版**，链接器有 **32KB 上限**，超了会报：

```
L6047U: The size of this image (xxxxx bytes) exceeds the maximum allowed for this version of the linker
```

当前余量只有约 **860 字节**（已经很紧）。若后续继续加代码触发此错误，
要么注册 MDK，要么换 AC6/GCC 编译，或者继续裁剪无用代码。

## 7. 版本记录

| 版本 | 变更 |
|------|------|
| V1.0 | 初版：SPI2 Slave + 软件 NSS + EXTI 帧边界 + DMA 收发 |
| V1.1 | 增加**全 0xFF 毛刺帧过滤**（解决 Master 板上电瞬间疯狂打印假帧） |
| V1.2 | 修复帧长累加 Bug：`HAL_SPI_DMAStop()` 为空壳函数导致 HAL 状态机卡在 BUSY、DMA 计数不重装 |
| V1.3 | **改为环形 DMA 常驻架构**：SPI 不再反复关停，彻底解决"首字节错位/丢字节"和"TX FIFO 残留导致 Master 读到旧字节"；不再使用 HAL 的 SPI DMA 状态机与 DMA 中断；新增信号线自检 + 寄存器快照 + 运行诊断计数；空壳化 DMA 中断函数释放约 4KB 以适配 MDK-Lite 32KB 上限 |
| V1.4 | **应答 pattern 改为 16 个 `0xA5`（位对齐探针）**，从机侧**自动反推位偏移量并打印结论** —— 递增斜坡 pattern 会让任何位偏移"看起来仍然正常"，换成 `0xA5` 后偏几位一眼可判；新增 `SPI_DEMO_MODE` 可选 Mode0~3 便于排查主从相位不匹配；RX FIFO 排空判据改为 `RXP/RXWNE/RXPLVL` 组合（`DSIZE=8` 时只等 `RXWNE` 会漏掉未凑满 32bit 的尾字节）；新增单帧长度上限 256 字节防 NSS 漏沿；打印时关中断取整帧，避免读到"半新半旧"混合数据；上电清空 RX 缓冲 |
| V1.5 | **片选改为硬件 NSS**（`SPI_NSS_MODE=0`）：PB12 走 AF5 交给 SPI2 硬件做真片选，NSS 无效期间 SPI 忽略 SCK。修复软件 NSS（`SSI` 恒 0，从机"永久选中"）导致的**整帧偏移 1 bit** —— 实证：Master 发 `A5` 收到 `D2`（=A5 循环右移 1 位），MISO 上为 `70 72 74 76...`（=38~3F 各左移 1 位） |
