# 42_spi_slave — STM32H750 SPI2 从机(Slave) Demo

正点原子 **M100Z-M7 最小系统板(STM32H750VBT6)** 的 SPI2 从机实验工程。

---

## 1. 功能

| 项目 | 说明 |
|------|------|
| 外设 | SPI2，**从机模式** |
| 引脚 | `PB12=NSS` `PB13=SCK` `PB14=MISO` `PB15=MOSI`（AF5） |
| 时序 | **Mode0**（CPOL=0, CPHA=0），MSB 先发，8bit；模式由 `SPI_DEMO_MODE` 可选 0~3 |
| 片选 | 默认**硬件 NSS**（PB12 走 AF5）；`SPI_NSS_MODE=1` 可切回软件 NSS |
| Master 时钟 | 支持 **100kHz ~ 10MHz**（SPI2 内核时钟 PCLK1=120MHz） |
| Master 写 | 一个 NSS 脉冲 = 一帧。NSS 上升沿后，从机把**本帧**数据以十六进制从 **串口1 @115200** 打印 |
| Master 读 | 从机每帧回发 16 字节 **`0xA5`** |
| 单帧上限 | **512 字节**（`SPI_RX_BUF_SIZE`） |
| 清空策略 | **每帧结束即清空 RX 缓冲并重装 DMA**，帧与帧之间不累计、不残留 |
| 帧间间隔 | NSS 高电平建议 ≥ 50us |

## 2. 接线

### SPI 四线（必须全部接，且必须共地）

| STM32 (M100Z-M7) | 方向 | Master (RK3576 等) |
|---|---|---|
| `PB12` NSS | ← | CS / SS |
| `PB13` SCK | ← | SCLK |
| `PB14` MISO | → | MISO |
| `PB15` MOSI | ← | MOSI |
| `GND` | — | GND（**必接**） |

> **NSS 一定要接。** SPI 协议本身没有"帧"的概念，从机完全靠 NSS 上升沿判断一帧结束。
> 不接 NSS 就不会打印，数据也会粘连。

### 串口（看打印）

板上没有 USB 转串口芯片，`PA9(TX)/PA10(RX)` 引在 **P3 调试排针**（4x2，丝印 `SWD & USART1`）。

| STM32 | Mini HS-DAP / USB-TTL |
|---|---|
| `PA9` (TX) | RXD |
| `PA10` (RX) | TXD |
| `GND` | GND |

串口参数：**115200-8-N-1**，用 XCOM / SSCOM / MobaXterm 打开对应 COM 口。

## 3. 工作原理（V2.0：每帧独立 + 收完即清空）

一句话：**一个 NSS 脉冲 = 一帧 = 一次「停 DMA → 取数据 → 清空缓冲 → 重装 DMA」**。

```
        NSS 上升沿（一帧结束）
              │
              ├─ 1. 等 SPI 的 RX FIFO 排空（保证最后一个字节已落进 RAM）
              ├─ 2. 停掉 RX / TX 两路 DMA 流
              ├─ 3. len = 缓冲大小 - NDTR        <- NORMAL 模式下 NDTR 一路递减
              ├─ 4. 把本帧数据搬到打印缓冲
              ├─ 5. RX 缓冲整块清零               <- 「每次接收都清空」就在这一步
              ├─ 6. 重装 RX / TX DMA（NDTR 与地址复原）并重新使能
              └─ 7. 置打印标志 ──> 主循环十六进制打印（不在中断里做慢速打印）
                     │
                     v
              下一帧从 缓冲[0] 开始，干净的
```

### 为什么从 CIRCULAR 换成 NORMAL

V1.3~V1.5 用的是**环形（CIRCULAR）DMA 常驻**：DMA 写指针在一条"环形跑道"上绕圈，
靠 `本帧长度 = (上次NDTR - 本次NDTR) & 511` 来切帧。这套模型有两个硬伤：

- **上一帧的数据还留在环上**。只要帧边界差一点（丢一个 NSS 边沿、或者最后一个字节
  还没搬完就先把 NDTR 读走了），就会把**上一帧的尾巴当成本帧的开头**打出来 ——
  现象正是"数据像是累计的、混着上一次的"。
- NDTR 是"剩余计数"，帧长要靠**两次采样的差值**推出来，凭空多了一个会出错的环节。

V2.0 改成 **NORMAL 模式**：每帧都从 `缓冲[0]` 重新开始写，物理上就不可能混；
长度直接 `len = 大小 - NDTR`，不需要差值。

### 为什么"停 DMA"是安全的

「停 DMA → 取数 → 清零 → 重装」整套动作全部发生在 **NSS 为高（片选无效）期间**。
SPI Mode0 下空闲 SCK 为低，Master 在片选无效时不会打时钟，所以这段时间的操作
不会丢数据。整套动作在 480MHz 下约 **2~3us**，而两帧间隔通常是毫秒级。

### 三个必须知道的 H7 坑（都已规避）

| # | 坑 | 本工程的处理 |
|---|---|---|
| 1 | `HAL_SPI_DMAStop()` 在 H7 上是**空壳函数**（只置一个错误码就返回），拿它停 SPI 的 DMA 会让句柄 State 卡死、`NDTR` 不重装 | 完全不调用它。DMA 的启停自己写（见 `dma_stream_reload()`），**只动 DMA 的 `EN` 位，绝不碰 SPI 的 `SPE`** |
| 2 | H7 的 SPI 从机必须"**先武装好，再来时钟**"；SPI 的 TX FIFO 会被 DMA 预填充，而 `SPE=0` 并不保证清空 FIFO | SPI **使能一次就永不关闭**，只重装 DMA。TX 应答每帧都是同一个 `0xA5`，即使 FIFO 有残留也是同一个值 |
| 3 | HAL 的 `HAL_SPI_TransmitReceive_DMA()` 会顺带开 OVR/UDR/FRE/MODF 中断并维护内部 State 机，一旦报错就停流、State 置 ERROR，重新武装直接返回 `HAL_BUSY` | 不用 HAL 的 SPI DMA API，不启用任何 DMA 中断。全片唯一中断源是 `NSS` 的 EXTI |

**`dma_stream_reload()` 里最关键的是那个等待：**

```c
CLEAR_BIT(s->CR, DMA_SxCR_EN);            /* 停流 */
while ((s->CR & DMA_SxCR_EN) != 0UL) { }  /* <- 必须等硬件真的清 0 */
s->NDTR = ndtr;                           /* 只有 EN=0 时才写得进去 */
```

DMA 的 `NDTR`/`M0AR`/`PAR` **只能在流 `EN=0` 时写**，而 `EN` 是由硬件在几个时钟
周期后才清掉的。不等这一步就写 `NDTR`，写入会**静默失效** —— 这就是
"帧长累加 16 → 32 → 48"那类 Bug 的真正来源。

### 其他关键设计点

- **硬件 NSS（`SPI_NSS_MODE=0`，默认）**：PB12 走 `AF5` 交给 SPI2 硬件做真片选，
  片选无效（高）期间 SPI 硬件**直接忽略 SCK**。这是根治"整帧数据偏若干 bit"的关键 ——
  偏 bit 的根源就是从机在片选无效期间也跟着 SCK 移位，移位寄存器相位一漂移就回不来。
  PB12 同时保留 EXTI（上升沿切帧）：EXTI 取自引脚输入缓冲，与 `MODER` 无关，
  所以「硬件片选」和「上升沿切帧」可以并存。
- **软件 NSS（`SPI_NSS_MODE=1`）**：`SSI=0` → 内部片选为低 → 从机常选中（MISO 常驱动），
  只适用于单从机总线。保留用于 A/B 对比。

  > 一个容易搞反的点：`SSI` 的值就是**内部片选电平**。HAL 只在
  > 「从机 + `NSSPolarity=HIGH`」或「主机 + `LOW`」时才置 `SSI=1`；
  > 本工程是**从机 + `LOW`**，HAL 不置 `SSI`，保持复位值 `0`。
  > `SSI=0` + 低有效 = **选中**，这才是对的。

- **应答数据用 `0xA5` 而非 `30 31 32...`**：递增斜坡被任何位偏移后**仍然是递增斜坡**，
  肉眼和逻辑分析仪都分不出来，是诊断上最坏的测试数据。详见 3.1。
- **Cache 一致性**：缓冲区 32 字节对齐、位于 **AXI SRAM（`0x24000000`）**，DMA1 可访问。
  （注意：**绝不能放 DTCM `0x20000000`**，H7 的 DMA1/DMA2 访问不了。）
  DMA 写内存后 CPU 读前做 `SCB_InvalidateDCache_by_Addr`；
  CPU 清零后做 `SCB_CleanDCache_by_Addr`。
- **空壳化 DMA 中断服务函数**（`DMA1_Stream0/1_IRQHandler` 留空占位），
  让链接器丢掉 `HAL_DMA_IRQHandler` 等约 4KB 代码 —— 见第 5 节的 32KB 限制说明。

### 3.1 为什么应答数据用 0xA5，而不是 30 31 32...

**递增斜坡 `30 31 32 ... 3F` 是诊断上最坏的选择。** 它是一条斜坡，任何一个位的偏移，
移完仍然是一条递增斜坡：

| 实际线上的数据 | 逻辑分析仪 / 上位机看到的 |
|---|---|
| `30 31 32 33 34 35 36 37`（正确） | 干净漂亮的递增，**看着完全正常** |
| 整体偏 1 bit | `60 62 64 66 68 6A 6C 6E`（**还是递增**） |
| 整体偏 1 bit，且起点落在 pattern 后半段 | `70 72 74 76 78 7A 7C 7E`（**还是递增**） |

三种情况肉眼看都像"递增"，这就是之前"看着不对、但说不清错在哪"的根源 ——
用逻辑分析仪抓到的 `70 72 74 76 78 7A 7C 7E`，正是斜坡整体移位后的结果，
和"数据源错了"看起来一模一样。

**`0xA5 = 1010_0101` 的 8 种循环移位互不相同：**

```
A5  →  4B  →  96  →  2D  →  5A  →  B4  →  69  →  D2  →  (回到 A5)
```

于是位偏移量可以**一眼读出来**：

| 读到 | 结论 |
|---|---|
| `A5 A5 A5 ...` | 位对齐正确 |
| `4B 4B 4B ...` | 整体偏 1 位（一个方向） |
| `52 52 52 ...` | 整体偏 1 位（另一个方向） |
| `96 96 96 ...` | 整体偏 2 位 |

而且 `0xA5` 只有 **1 字节周期**，无论从哪个字节边界开始读都一样 ——
不会再有"读到 pattern 第二半段"的困扰。

**如果读到的是循环移位后的值**（例如 `4B` 或 `D2`）：说明整帧偏了位。
先确认 `SPI_NSS_MODE = 0`（硬件 NSS）已生效、且主从**共地**；
若依旧，把 `SPI_DEMO_MODE` 依次改成 `1 / 2 / 3`（对应 Mode1/2/3）重新编译烧录，
同时把 Master 改成同一模式。

## 4. 上电输出与运行诊断

### 4.1 寄存器快照（每次上电打印一次）

```
---- 寄存器快照 ----
 SPI2  : CR1=... CFG1=... CFG2=... SR=...
 DMA_S0: CR=... NDTR=512 M0AR=... (RX, NORMAL 512字节)
 DMA_S1: CR=... NDTR=16  M0AR=... (TX, NORMAL 16字节)
```

`CR` 的 bit0(`EN`) 应为 **1**，bit8(`CIRC`) 应为 **0**；`NDTR` 应等于缓冲大小。
`M0AR` 应分别指向 `g_spi_rx_buf` / `g_spi_tx_buf`。

### 4.2 ★ 心跳（每 2 秒一次，无条件打印）—— 排查"串口没反应"的第一判据

```
[心跳] 12 s | NSS=12 帧=6 空=0 | 错 OVR=0 UDR=0 FRE=0 | SPI_EN=1
```

| 字段 | 含义 | 正常值 |
|---|---|---|
| 开头秒数 | 上电后运行的秒数 | **每 2 秒 +2，一直在涨** |
| `NSS` | 收到多少次 NSS 上升沿 | 与 Master 发起的传输次数一致 |
| `帧` | 成功取到数据并打印的帧数 | 与 Master 发起的写次数一致 |
| `空` | 长度算出来是 0 的帧（多半是 NSS 线上的毛刺） | Master 上电时可能涨几次，之后不动 |
| `OVR` | RX FIFO 溢出（收得太快、DMA 没来得及搬） | **恒为 0**（不是 0 就是接收侧真故障） |
| `UDR` | TX FIFO 欠载（从机要发时 FIFO 是空的） | 从机 TX 只准备固定长度时**每帧 +1 属正常**，见 4.4 |
| `FRE` | TI 模式帧错误 | **恒为 0**（本工程不用 TI 模式） |
| `SPI_EN` | SPI2 的 `SPE` 位 | **恒为 1** |

**拿它一刀切开问题：**

| 现象 | 结论 |
|---|---|
| 心跳每 2 秒准时出现 | 程序在跑、串口通 → 问题只在 SPI 数据通路，看 4.3 |
| 心跳完全不出现 | 板子**根本没跑起来**（没烧进去 / 没复位 / 串口线或波特率不对），与 SPI 逻辑无关 |
| 心跳出现但秒数不涨 | 程序卡死在某个循环里 |

### 4.3 正常打印长什么样

每次传输（一个 NSS 脉冲）打印一帧，**帧与帧之间不累计**：

```
[SPI2 Slave] 本帧 8 字节:
A5 A5 A5 A5 A5 A5 A5 A5
```

**Master 端测试命令（RK3576 / spidev_test）：**

```bash
# 发 8 字节，同时读回 8 字节（spidev_test 的 -p 是全双工）
spidev_test -D /dev/spidev2.0 -s 100000 -p "\xA5\xA5\xA5\xA5\xA5\xA5\xA5\xA5"

# 看串口打印：应当出现 8 个 A5；TX 侧读回也应当是 8 个 A5
```

**判据：**

| 串口显示 | 结论 |
|---|---|
| `A5 A5 A5 ...` | ✅ 位对齐正确，收发都正常 |
| `4B 4B ...` 或 `D2 D2 ...` | 整帧偏了位 → 先查共地；仍偏再把 `SPI_NSS_MODE` 改成 `0`（硬件 NSS）试 |
| 值五花八门 | 不是单纯位偏移 → 查共地、SCK 频率是否过高、线上有无过冲振铃 |
| 帧长每次都比预期多/少 | NSS 边沿数异常，看 `[诊断]` 行的 `NSS边沿` |

### 4.4 关于 `UDR`（TX 欠载）

**从机 TX 只准备了 16 字节（`SPI_TX_PATTERN_LEN`），而 Master 读的字节数 ≥ 16 时，
TX FIFO 会被读空 → 置 `UDR`。** 每帧 +1 是**预期行为**，不是 bug：

- 数据仍然正确 —— 欠载时从机补发什么由 `CFG1.UDRCFG` 决定（HAL 对从机设的是固定行为），
  实测 Master 读回的内容没有受污染。
- 想让 `UDR` 归零：把 `SPI_TX_PATTERN_LEN` 改成 `SPI_RX_BUF_SIZE`，
  并把 `g_spi_tx_buf` 同步改大（512 字节，全填 `0xA5`），TX DMA 每帧就给满。
  ⚠ 副作用：帧结束时 TX FIFO 里会残留若干字节（内容相同，纯 pattern 场景无影响；
  若以后要"每帧回发不同内容"，需另想办法在帧边界刷新 TX FIFO）。

**判断顺序**：先看是 `OVR` 还是 `UDR` 在涨 ——
`OVR` 涨 = 接收侧真故障（查 DMA 是否被卡住）；
`UDR` 涨 = 发送侧给少了（按上面处理或直接接受）。

## 5. ⚠ Keil 版本限制：32KB

本工程用 **armcc V5.06u7 (AC5)** 编译，镜像大小约 **28008 字节**
（`Code=26896 RO=924 RW=48`，另有 `ZI=5984` 不占镜像）。

如果 Keil 是 **Lite / 未注册版**，链接器有 **32KB 上限**，超了会报：

```
L6047U: The size of this image (xxxxx bytes) exceeds the maximum allowed for this version of the linker
```

当前余量约 **4900 字节**。若后续继续加代码触发此错误，
要么注册 MDK，要么换 AC6/GCC 编译，或者继续裁剪无用代码。

| 版本 | 变更 |
|------|------|
| V1.0 | 初版：SPI2 Slave + 软件 NSS + EXTI 帧边界 + DMA 收发 |
| V1.1 | 增加**全 0xFF 毛刺帧过滤**（解决 Master 板上电瞬间疯狂打印假帧） |
| V1.2 | 修复帧长累加 Bug：`HAL_SPI_DMAStop()` 为空壳函数导致 HAL 状态机卡在 BUSY、DMA 计数不重装 |
| V1.3 | **改为环形 DMA 常驻架构**：SPI 不再反复关停，彻底解决"首字节错位/丢字节"和"TX FIFO 残留导致 Master 读到旧字节"；不再使用 HAL 的 SPI DMA 状态机与 DMA 中断；新增信号线自检 + 寄存器快照 + 运行诊断计数；空壳化 DMA 中断函数释放约 4KB 以适配 MDK-Lite 32KB 上限 |
| V1.4 | **应答 pattern 改为 16 个 `0xA5`（位对齐探针）**，从机侧**自动反推位偏移量并打印结论** —— 递增斜坡 pattern 会让任何位偏移"看起来仍然正常"，换成 `0xA5` 后偏几位一眼可判；新增 `SPI_DEMO_MODE` 可选 Mode0~3 便于排查主从相位不匹配；RX FIFO 排空判据改为 `RXP/RXWNE/RXPLVL` 组合（`DSIZE=8` 时只等 `RXWNE` 会漏掉未凑满 32bit 的尾字节）；新增单帧长度上限 256 字节防 NSS 漏沿；打印时关中断取整帧，避免读到"半新半旧"混合数据；上电清空 RX 缓冲 |
| V1.5 | **片选改为硬件 NSS**（`SPI_NSS_MODE=0`）：PB12 走 AF5 交给 SPI2 硬件做真片选，NSS 无效期间 SPI 忽略 SCK。修复软件 NSS（`SSI` 恒 0，从机"永久选中"）导致的**整帧偏移 1 bit** —— 实证：Master 发 `A5` 收到 `D2`（=A5 循环右移 1 位），MISO 上为 `70 72 74 76...`（=38~3F 各左移 1 位） |

### V2.4 (2026-09-17 18:56) - 硬件NSS, 每帧重新对齐

**现象**: TX 修复后, Master 读回 4B 4B... (A5左移1位), 从机收到 D2 D2...(A5右移1位); 
首次传输前2字节对, 错位发生在帧间; 从机第1帧只收1字节, 心跳 空=2 (RK3576 把一次传输的CS拆成多段)。

**根因**: 软件NSS(SSM=1, 从机常选中)下 SPI 位计数器**永不清零**, 帧间任何多余/丢失的 SCK 边沿
都会让字节边界永久滑 1 位, 双方向一起歪。

**修复**: (硬件NSS): CS 无效期间 SPI 硬件忽略 SCK, 每次 CS 拉低从 bit0 重新对齐。
编译 0E/0W, 镜像 28020B。

### V2.3 (2026-09-17 18:45) - 修复 TX DMA 地址对调

**现象**: RX 方向全通(本帧 16 字节 A5), 但 Master `spidev_test -v` 读回全 00; 逻辑分析仪抓波形: MOSI 解码 16xA5 正确, **MISO 一条平线**; 心跳 UDR=0。

**根因**: `dma_stream_reload()` 的 TX 调用把 PAR/M0AR 写反了——
STM32 DMA 规则是 **PAR=外设寄存器, M0AR=内存缓冲**（不分方向, 固定含义）。
V2.2 写成 `reload(Stream1, g_spi_tx_buf, &SPI2->TXDR, 16)`, 等于让 DMA
在每次 TX 请求时**从 TXDR 读数(恒0)写进 FIFO**:
- MISO 输出全 0（平线）
- FIFO 一直有数据 -> **UDR 不置位** -> 极难从错误计数发现
- 副作用: g_spi_tx_buf 每帧被 0 覆盖

**修复**: 两处调用改为 `reload(DMA1_Stream1, &SPI2->TXDR, g_spi_tx_buf, 16)`。
编译 0E/0W, 镜像 28016B。
